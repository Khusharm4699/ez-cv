# Personal Resume Skill (EZ-CV)

Your personal resume engine. A knowledge-base-driven, anti-fabrication resume
builder that keeps **one verified source of truth** (`data/profile.json`) and
generates every output from it with deterministic Python renderers.

The philosophy: **deterministic work runs in Python, the LLM is reserved for
judgment** (tailoring bullets, quantifying impact, critiquing prose). Regenerating
any output is a script call, never a hand-edit, so it stays free and consistent.

## When to use

Trigger when the owner says: "build my resume", "update my resume", "tailor my
resume to <JD>", "regenerate the HTML resume", "make a one-page version",
"resume critique", or points at a new job description.

## Architecture (extract once, generate many)

```
data/profile.json     <- single verified source of truth (the knowledge base)
data/profile.schema.json  <- field reference for profile.json
   |
   +-- scripts/build_html.py          -> output/<slug>_resume.html  (terminal theme, scrolling)
   |                                     + --compact -> ..._onepage.html   (one A4 page)
   |                                     + --public  -> ..._public.html     (phone hidden; safe to host)
   +-- scripts/build_html_ai.py       -> output/<slug>_resume_onepage_ai.html  (AI chat-UI theme, 1 page)
   |                                     + --public  -> ..._ai_public.html
   +-- scripts/build_html_editorial.py-> output/<slug>_resume_editorial.html  (light print-grade theme)
   |                                     + --compact / --public variants
   +-- scripts/build_html_sidebar.py  -> output/<slug>_resume_sidebar.html  (modern two-column theme)
   |                                     + --compact / --public variants
   +-- scripts/build_text.py          -> output/<slug>_resume.md + .tex   (ATS Markdown + LaTeX)
   |                               + --compact -> ..._onepage.md / .tex
   +-- scripts/_condense.py     -> shared one-page condenser used by --compact
   +-- scripts/_emphasis.py     -> shared **bold** + auto-metric bolding
   +-- scripts/_identity.py     -> per-person tokens (slug, monogram, handle, AI id, accent)
   +-- scripts/humanize_scan.py -> deterministic AI-fingerprint scan (CI-usable)
   +-- scripts/keyword_audit.py -> JD keyword coverage report (zero LLM tokens)
reference/  <- the playbooks the LLM follows when WRITING/EDITING content
output/     <- generated resumes (html, md, tex, pdf) + assets/
```

`<slug>` is derived from `header.name` (e.g. "Maya Iyer" -> `maya_iyer`). Nothing
about the person is hardcoded in the scripts — name, monogram, terminal handle,
AI assistant id, and the accent color all come from `data/profile.json`.

## Workflow

### Mode A — Regenerate (fast, no questions)
1. Read `data/profile.json`.
2. Full set: `python3 scripts/build_html.py` and `python3 scripts/build_text.py`.
   For PDF: `cd output && tectonic <slug>_resume.tex` (or `pdflatex`, or upload
   the `.tex` to Overleaf, or Print -> Save as PDF from the HTML).
3. One-page set: add `--compact` to both renderers, then
   `tectonic <slug>_resume_onepage.tex`. `--compact` reuses the same
   `profile.json` via `scripts/_condense.py` (summary -> 2 sentences; most recent
   role -> top 6 first-sentence bullets; older roles -> 3; awards capped to 2;
   entries tagged `"onepage":"drop"` removed; projects tagged
   `"onepage":"oneline"` collapsed) and a denser CSS/LaTeX profile.
4. Other HTML styles (all from the same `profile.json`, each takes `--compact`
   and `--public`):
   - `python3 scripts/build_html_ai.py` — AI chat-UI one-pager.
   - `python3 scripts/build_html_editorial.py` — light, print-grade single column
     (serif headings + sans body); best for recruiter/human review and clean print.
   - `python3 scripts/build_html_sidebar.py` — modern two-column (dark accent rail
     with contact/skills/education beside a light main column).
5. Public (hostable) HTML: add `--public` to hide the phone number while keeping
   email and profile links.
6. Section order:
   - **HTML** (terminal / AI / editorial / sidebar): Header -> Highlights (slim
     stat row) -> Summary -> Skills -> Experience -> Projects -> Speaking ->
     Education + Certs.
   - **Markdown / LaTeX (ATS)**: same order, Highlights omitted (the metrics
     already live in the bullets). Single-column, plain-unicode, standard
     headings, quantified reverse-chron bullets — built for ATS parsing.
   - **Awards** render as an "Awards" line on the experience entry that earned
     them, in every format.
   - **PDF page-break safety**: `\needspace` guards each entry so a role/dates
     header is never orphaned at the bottom of a page.
7. Open the outputs for the owner. Done.

### Mode B — Tailor to a JD
1. Save the JD to `data/target_jd.txt`.
2. Analyze with `reference/jd-analysis-method.md` (must-haves, nice-to-haves,
   keywords, seniority).
3. Run `python3 scripts/keyword_audit.py data/target_jd.txt` for coverage.
4. Re-order/re-weight `summary`, `skills`, and bullet emphasis toward the JD's
   must-haves. **Never invent experience** to cover a missing keyword — flag the
   gap (`reference/gap-coverage-plan.md`).
5. Re-run Mode A, then critique (Mode D).

### Mode C — From scratch / deep update
1. Gather facts with the EZ-CV interview question bank (or the owner's notes).
2. Insist on numbers (`reference/quantification-playbook.md`): before/after, %,
   count, time, scale, adoption. Mark each answer's provenance
   (`verified` / `estimate` / `placeholder`).
3. Write answers into `data/profile.json`. Generate (Mode A) + critique (Mode D).

### Mode D — Critique
1. `python3 scripts/humanize_scan.py` — deterministic enforcement of
   `reference/ai-fingerprint-rules.md` (banned words, -ing bullet endings,
   em-dash cap, triplet cap, sentence-length variety, passive voice). Fix every
   hard FAIL in `data/profile.json` and regenerate before continuing.
2. Fresh-eyes review with `reference/critique-framework.md` (five reader personas
   score eight dimensions). Save to `output/critique.md`.
3. Apply `reference/critical-rules.md` (verb discipline, provenance, no
   fabrication) on every edit.

## Emphasis markup

In `profile.json`, wrap key phrases in `**double asterisks**` to bold them. The
shared `_emphasis.py` also auto-bolds numeric impact metrics (percentages,
multipliers, counts with `+`, time spans, ranges) so you rarely mark numbers by
hand. Bare integers, version tokens (`3.x`), and years are left alone.

## Hard rules (non-negotiable)

- **No fabrication.** Every claim traces to verified source material or is a
  clearly-flagged estimate with `~`.
- **Numbers or it didn't happen.** Push every achievement toward a metric.
- **Gaps are flagged, never faked.**
- **Human voice.** Run the AI-fingerprint scan before declaring done.
- **Placeholders are loud.** Surface anything marked `placeholder`.

## Reference docs

- `reference/critical-rules.md` — anti-fabrication, provenance, verb discipline
- `reference/quantification-playbook.md` — turning vague claims into metrics
- `reference/jd-analysis-method.md` — reading a JD into requirements + keywords
- `reference/ai-fingerprint-rules.md` — banned words + human-voice scan
- `reference/critique-framework.md` — 5-persona / 8-dimension scoring
- `reference/gap-coverage-plan.md` — JD gap analysis + closing plan
- `reference/html-design-system.md` — terminal-theme design tokens

## Customize the look

Set `header.theme.accent` (and optionally `accent_dim`, `accent_print`) in
`profile.json` to recolor every theme at once — the accent propagates to the
terminal, AI, editorial, and sidebar HTML plus the PDF. Override `handle`,
`monogram`, `role_slug`, or `ai_id` in `header` to fine-tune the terminal prompt
and the AI theme labels.
